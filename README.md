### Основные (бизнес) задачи
1. Сформировать архитектуру приложения.
- (``BusContract``) Добавить класс Автобус.
	
2. (``SorterDataBusCommand``) Класс - команда, из которого будет запускаться приложение.
- - использовать паттерн внедрения зависимостей для класса и создать интерфейсы, которые будут внедряться:
- - (``BusContractStorage``) получения данных.
- - (``BusContractSorter``) сортировка.
- Реализовать алгоритм (метод ``execute()``).
- - Получение данных.
- - Сортировка.
- - Вывод полученных данных.
		
3. (``BusStoragable``) Интерфейс: метод формирующий массив данных и его длину (объект реализующий этот интерфейс должен внедряться в SorterDataCommand).
- класс, получающий данные из файла.
- класс, данные которые формируются рандомно.
- класс, которые вводятся вручную (через класс Scanner?).
	
4. ``BusDataValidator`` Класс, который валидирует данные.

5. ``BusBuilder``. Реализовать класс, используя паттерн билдер.

6. Классы, которые сортируют данные по 3-м полям класса и реализующий интерфейс ``BusSorterable``.
- ``BusNumberSorter`` (сортирующий по номеру).
- ``BusModelSorter`` (сортировка по модели).
- ``BusMileageSorter`` (сортировка по пробегу).

7. Основной класс ``TaskFive``. Реализовать скрипт, которая будет выполняться по сценарию:
- Программа выполняется в цикле. Выход из цикла возможен только путем соответствующего выбора пользователя. При выборе сценария "сортировка автобусов" процесс работает следющим образом:
- - Ожидание от пользователя выбора "получения данных". В зависимости от выбора создать enum ``StorageTypeEnum``.
- - Ожидание от пользователя выбора "сортировки данных". В зависимости от выбора создать enum ``SorterTypeEnum``.
- - Передать методу ``execute()`` класса ``SorterDataBusCommand`` эти enum данные.
